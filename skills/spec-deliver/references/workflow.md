# Spec Deliver Workflow Reference

## End-to-End Flow

```
Engineer has idea
    │
    ▼
/spec-deliver "high level description"
    │
    ├─ Phase 1: EXPLORE
    │   └─ /opsx:explore — interactive Q&A to refine the concept
    │   └─ Human answers questions, refines scope
    │
    ├─ Phase 2: PROPOSE
    │   └─ /opsx:propose — generates all artifacts:
    │       ├─ proposal.md (why)
    │       ├─ specs/<capability>/spec.md (what, with Tracey r[...] markers)
    │       ├─ design.md (how)
    │       └─ tasks.md (steps, with Tracey IDs on each task)
    │
    ├─ Phase 3: REVIEW ← HUMAN QUALITY GATE
    │   └─ Engineer reviews specs, edits if needed
    │   └─ Says "approved" to proceed
    │
    ├─ Phase 4: DELIVER
    │   └─ Ralph loop creates an agent team:
    │       ├─ Lead agent analyses tasks and creates team
    │       ├─ Teammates implement tasks in parallel
    │       ├─ Adds r[impl ...] to production code
    │       ├─ Adds r[verify ...] to test code
    │       └─ Exits when coverage = 100% and all tasks done
    │   └─ Cleanup: removes ralph-loop state files
    │
    ├─ Phase 5: QA ← CODE REVIEW + BUILD + TEST GATE
    │   └─ qa-code-reviewer sub-agent reviews diff for quality/security/patterns
    │   └─ Detect build system and run build (if applicable)
    │   └─ Detect test framework and run full test suite
    │   └─ Report results, block on critical issues (user can fix or skip)
    │
    ├─ Phase 6: VERIFY
    │   └─ tracey_status — final coverage report
    │   └─ tracey_uncovered — any gaps
    │   └─ /opsx:verify — completeness, correctness, coherence
    │
    ├─ Phase 7: ARCHIVE
    │   └─ /opsx:archive — syncs delta specs to stable, archives change
    │
    └─ Phase 8: PR
        └─ gh pr create — with spec traceability in description
```

## State File

The orchestrator writes `.claude/spec-deliver.local.md` to track progress:

```yaml
---
change: add-user-auth
phase: delivering       # exploring | proposing | reviewing | delivering | qa | verifying | archiving | complete
approved: true
max_iterations: 30
started: 2026-03-22
updated: 2026-03-22
---

Original idea text here
```

## Resume Logic

On re-invocation, the orchestrator:
1. Detects the state file
2. Cross-references with on-disk artifacts (change dir, task checkboxes, archive status)
3. Determines the actual current phase
4. Resumes from there

## Tracey Integration

### In Specs (generated by OpenSpec)
```markdown
### Requirement: User can export data
> r[data-export.user-can-export-data]
The system SHALL allow users to export their data in CSV format.
```

### In Tasks (generated by OpenSpec)
```markdown
- [ ] 2.1 Implement data export function (r[data-export.user-can-export-data])
- [ ] 2.2 Write tests for data export (r[verify data-export.user-can-export-data])
```

### In Code (added during delivery)
```typescript
// r[impl data-export.user-can-export-data]
export function exportUserData(userId: string): CsvFile {
  // ...
}

// r[verify data-export.user-can-export-data]
test('exports user data as CSV', () => {
  // ...
});
```

## Completion Criteria

The agent team's work is complete when:
1. All tasks in tasks.md are checked `[x]`
2. `tracey_uncovered` returns 0 for the change's requirements
3. `tracey_untested` returns 0 for the change's requirements
4. All tests pass

The QA phase then validates:
5. Code review sub-agent finds no critical issues
6. Project builds successfully (if applicable)
7. Full test suite passes (not just tests from this change)
